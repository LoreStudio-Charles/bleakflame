## 1. THE GAME IS NOW "RISE OF ADÉN"

Renamed from *Bleakflame*. **Adén** is the Wardens' word for idiots — `tu` = the,
`adé` = idiot (sing.), `adén` = idiots (pl.), so **Tu Adén** = The Idiots
(supersedes ADO'VIETES). The title states the Saga's ending on the box and spoils
nothing, because the player cannot read it until the late reveal teaches them.

> **THE SAVE DIRECTORY IS STILL `Bleakflame` AND MUST STAY THAT WAY.**
> Godot derives `user://` from `config/name`, so the rename pins BOTH
> `application/config/use_custom_user_dir=true` and
> `config/custom_user_dir_name="Godot/app_userdata/Bleakflame"` in project.godot.
> **Both lines are required** — `custom_user_dir_name` is ignored without the flag,
> and with the flag on Godot drops the `Godot/app_userdata/` prefix it normally
> adds, so the full relative path has to be spelled out. The first attempt at this
> silently pointed at `app_userdata/Rise of Adén/` and found no save. Caught by
> running the game, not by reading the code.

`assets/ships/future/bleakflame_legendary` is no longer the titular ship. It is
still the endgame prize; open question whether it earns its name in-fiction or
takes a new one.

## 6. Testing — read before trusting a green run

- **The 5 "failures" are a scratch-runner artefact**, not real. `test_chat` prints
  "OK", `test_affixes` "all passed", and the runner only recognises "ALL PASS";
  `test_gate` and `test_ground_notice` are cut off by its 600-frame cap. All five
  pass when run individually. Fix the runner rather than eyeballing past it.
- **ALWAYS pass `--quit-after N` to scene tests.** A script that fails to compile
  hangs forever with **empty output**, and two orphaned Godot processes were left
  burning 1.6GB this session because of exactly that.
- **A new `class_name` needs `--import`** before anything can reference it.
- **SABOTAGE-VERIFY every new assertion.** Three tests this session agreed with the
  bug they were written alongside, because assertion and code came from the same
  wrong idea. A test that cannot fail is not a test.
- **Screenshots find what tests cannot.** The `%d/%d` banner bug shipped since the
  initial commit and survived 660 dock assertions — it is invisible in source
  because both call sites look correct in isolation. Drive the real scene and grab
  `get_viewport().get_texture().get_image().save_png()` (what F12 does).

## 7. The catalogue (added 2026-07-27)

`Research.catalogued` — every subject the pilot has put on file, keyed by DATA KEY
(a hull's `resource_path`, never its display name). Persisted inside the existing
`"research"` save key; absent in older saves, which start empty and re-earn it.

Keying off the **hull** rather than the node is what makes it a catalogue instead
of a per-instance flag: a respawned pirate is not a fresh discovery, and a second
Kestrel is the same subject. First of a class pays full and writes a Captain's Log
line (so the codex is readable today with no new UI); a repeat is refused in
`_try_start_scan`, **before** the 3.2s channel and before any spend. A subject with
no key — the station — is refused too; that hole was the easiest faucet in the game.

**This is meant to grow into a player-facing codex.** The user's words: *"catalog
is great and would be a fun feature for players."* The data is already there and
already persisted; what is missing is a screen to read it on, and a reason to chase
completion (a Scout/Xenology payoff is the obvious hook).
